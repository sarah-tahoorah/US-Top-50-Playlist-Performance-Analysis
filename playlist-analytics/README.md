# United States Top 50 Playlist Performance and Song Popularity Trend Analysis

An end-to-end, password-protected analytics project over daily Spotify-style **Top 50
playlist snapshots**, built for a record-label use case (Atlantic Recording Corporation):
artist promotion, release timing and marketing-spend decisions.

This is **historical analytics only** — there are no prediction or recommendation models.

---

## Quick start

```bash
# 1. install dependencies
pip install -r requirements.txt

# 2. (optional) regenerate the synthetic dataset — one is already included
python -m src.generate_data

# 3. (optional) print the data-quality report to the terminal
python -m src.data_pipeline

# 4. launch the dashboard
python -m streamlit run app.py
```

Then open the URL Streamlit prints (default <http://localhost:8501>).

### Logging in

| Username | Password |
|---|---|
| `admin` | `Atlantic2024!` |

This is a **demo account** — change it before any real deployment. Passwords are stored
only as bcrypt hashes in `config/credentials.yaml`; no plaintext password appears
anywhere in the source. Nothing renders until you authenticate, and a **Logout** button
sits in the sidebar.

**Add or change a user:**

```bash
python -m config.make_credentials alice "S0me-Strong-Pass" "Alice Nguyen"
```

The script hashes the password with bcrypt and writes it into
`config/credentials.yaml`, creating the file if needed. Also change
`cookie.key` in that file to a random string for any shared deployment.

## Data

`data/sample_playlist_data.csv` — **synthetic sample data**, generated by
`src/generate_data.py`. It is *not* real Spotify or Atlantic data. It was produced to
mirror the production schema and statistical behaviour: 120 consecutive daily snapshots,
118 unique songs, 19 unique lead artists, lifecycle-driven rank churn (entry → climb →
peak → decay → exit), correlated popularity drift, and a small, deliberate amount of
dirt (missing popularity values, mis-cased artist names, duplicate rows) so the
validation stage has real work to do.

To use real data, drop a CSV with the same columns at
`data/sample_playlist_data.csv` (or pass a different path to
`src.data_pipeline.load_clean`):

| Column | Description |
|---|---|
| `date` | Date of playlist snapshot |
| `position` | Playlist rank (1–50) |
| `song` | Song title |
| `artist` | Artist(s), `feat.` variants supported |
| `popularity` | Popularity score (0–100) |
| `duration_ms` | Song duration in milliseconds |
| `album_type` | `Single` / `Album` |
| `total_tracks` | Number of tracks on the parent album |
| `is_explicit` | Explicit content flag |
| `album_cover_url` | Album artwork URL |

## Pipeline

**Step 1 — ingestion & validation** (`src/data_pipeline.py`)
Validates that `position` falls within 1–50, reports missing values, removes duplicate
`(song, artist, date)` keys (keeping the best rank), standardises artist formatting
(whitespace, casing, canonical ` feat. ` separator) and derives `primary_artist`.
Produces a **data-quality report** shown in the dashboard's *Data quality* tab.

**Step 2 — feature engineering** (`src/features.py`)
Days on Chart · Average Rank · Best Rank Achieved · Rank Volatility Index (std dev of
daily rank) · Popularity Trend Score (7-day rolling mean) · Duration in minutes · rank
velocity · Artist Dominance Index.

**Step 3 — analysis modules** (`src/analysis.py`), one dashboard tab each:

1. Playlist ranking analysis — rank distribution, movement patterns, entry/exit, fast risers vs. slow decliners
2. Song-level performance — longest-charting, highest popularity, peak-vs-longevity quadrants
3. Artist performance — unique songs, chart-days, dominance over time
4. Popularity score analytics — popularity/rank correlation, Top 10/20/50 bands, stability vs. volatility
5. Content attribute analysis — explicit vs. clean, single vs. album, duration, album size

**Step 4 — KPIs** surfaced at the top of the dashboard:

| KPI | Definition |
|---|---|
| Days on Chart | Distinct snapshot dates a song appears — longevity |
| Average Rank | Mean daily position |
| Rank Volatility Index | Standard deviation of daily rank (lower = steadier) |
| Popularity Score Trend | 7-day rolling mean popularity, with delta vs. the prior 7 days |
| Artist Dominance Index | `100 × (0.50 × norm(chart-days) + 0.30 × norm(unique songs) + 0.20 × (50 − avg rank)/49)` |
| Explicit Content Share | % of chart slots held by explicit tracks |

## Notes

- Requires Python 3.10+.
- `streamlit-authenticator` is the preferred login backend; if it is unavailable the app
  falls back automatically to an equivalent bcrypt-verified `st.session_state` gate with
  the same credentials file. No page content renders in either case until login succeeds.
- `plotly`'s OLS trendline on the popularity/rank scatter requires `statsmodels`, which is
  pinned in `requirements.txt`.
